# 🌐 OSSGrid

> **A free, no-login index of open-source mentorship programs.** Google Summer of Code and LFX Mentorship organizations, past projects, mentors and public proposals in one place. Outreachy, GirlScript Summer of Code, MLH Fellowship and Summer of Bitcoin are next.

[![Sync LFX](https://github.com/rajatrsrivastav/ossgrid/actions/workflows/sync-data.yml/badge.svg)](https://github.com/rajatrsrivastav/ossgrid/actions/workflows/sync-data.yml)
[![Sync GSoC](https://github.com/rajatrsrivastav/ossgrid/actions/workflows/sync-gsoc.yml/badge.svg)](https://github.com/rajatrsrivastav/ossgrid/actions/workflows/sync-gsoc.yml)

| Route | What it is |
|---|---|
| `/gsoc` | Every GSoC organization since 2016, projects per year, ideas lists |
| `/lfx` | Every LFX Mentorship organization since 2019, projects per term, mentors |
| `/proposals` | Public GSoC proposals indexed from community archives (links only) |
| `/guide` | The contributor playbook with a checklist per program |
| `/contribute` | How to contribute to OSSGrid and indexed repositories |
| `/contributors` | Approved OSSGrid contributors and GitHub repository contributors |
| `/programs/<id>` | Preview page for programs that are not indexed yet |

Programs live in one registry, `src/data/programs.ts`. Flip a program to `live` (with a route and a data file) and the header, landing page, footer, sitemap and search follow.

## ✨ Features

- 🔍 **Fuzzy Search** — Instantly search across organizations, projects, technologies, and mentor names.
- 🎯 **Multi-facet Filtering** — Filter by term, year, category, technology stack, and quick shortcuts.
- 🌗 **Dark/Light Mode** — Token-based design system, see `DESIGN.md`.
- 🔗 **Shareable URLs** — Filters sync to URL query parameters for shareable filtered views.
- 📱 **Fully Responsive** — Optimized grid layout from mobile to desktop.
- ⚡ **Pre-built program data** — Organization and project datasets are shipped as JSON. Contributor profiles are fetched from GitHub on demand.
- 🤖 **Auto-synced Data** — GitHub Actions updates project data daily from major open-source repositories.

## 📊 Data

All data is pre-built JSON under `public/data/`, regenerated by scheduled workflows that open pull requests. Counts in the UI are derived at build time; run `npm run audit:data` for exact numbers.

- **LFX** (`public/data/organizations.json`): every organization since 2019, every project with line-level provenance in `cncf/mentoring`, mentors, skills and issue links.
- **GSoC** (`public/data/gsoc/`): every organization since 2016 from gsocorganizations.dev and the GSoC archive, projects per year (lazy files), CNCF ideas lists from `cncf/mentoring` pinned to a commit, a prebuilt search index.
- **Proposals** (`public/data/proposals/`): public proposals indexed through the GitHub Trees API at pinned commits; records link to the originals and nothing is rehosted.
- Mentor emails may exist in the pipelines; they are never written to `public/`.

## 🚀 Getting Started

```bash
# Clone the repository
git clone https://github.com/rajatrsrivastav/ossgrid.git
cd ossgrid

# Install the locked dependencies
npm ci

# Run data integrity checks
npm run test:data
npm run audit:data

# Start the dev server
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) to view the application.

The contributor directory recognizes OSSGrid contributors only, using all-time GitHub history and maintainer-recognized entries. `npm run sync:contributors` updates the checked-in snapshot while preserving past contributors; the server API refreshes cached GitHub data and falls back to that snapshot on failure. Optional `GITHUB_TOKEN` credentials remain server-side. External repository contributor links open that repository’s GitHub contributors page. The creator is credited in the historical directory and in the footer at https://x.com/rajatrsrivastav. See [CONTRIBUTING.md](CONTRIBUTING.md#directory-recognition-and-synchronization) for maintenance details.

## 🤝 Contributing

New to the repository? Start with an [open issue](https://github.com/rajatrsrivastav/ossgrid/issues), especially one marked `good first issue`. Comment on the issue and wait for assignment before starting. If you found a problem, use the [bug, UI, or data issue forms](https://github.com/rajatrsrivastav/ossgrid/issues/new/choose) so a contributor has clear steps and acceptance criteria.

1. Fork the repository, clone your fork, and run `npm ci` followed by `npm run dev`.
2. Create a focused branch, such as `git switch -c fix/light-theme-network`. Change only what the assigned issue needs.
3. Run `npm run typecheck`, `npm run lint`, and `npm run check:copy`. For data changes, also run `npm run test:data` and `npm run audit:data`. Add a screenshot for visual changes.
4. Push your branch and open a PR against **`main`**. Put `Closes #<issue-number>` in the PR description and summarize what you changed and tested.
5. Wait for the checks and review. A static GitHub Pages preview URL is posted on the PR so you can inspect the prebuilt pages. Live API features are unavailable in that preview; test those locally.

The program datasets are generated ahead of time, so edit the source or import script for data fixes rather than hand-editing generated JSON. For issue ownership rules, the full PR checklist, and the repo layout, read [CONTRIBUTING.md](./CONTRIBUTING.md). The [contributor guide on the site](https://www.ossgrid.tech/contribute) explains the broader contribution path.

## 🔄 Data Pipeline Scripts

| Command | Description |
|---|---|
| `npm run test:data` | Run parser & data regression tests |
| `npm run audit:data` | Verify schema integrity, links, and source coverage |
| `npm run check:data` | Check byte-for-byte reproducibility against pinned upstream commit |
| `npm run sync:data` | Regenerate the LFX dataset from the pinned upstream commit |
| `npm run sync:gsoc` / `check:gsoc` | Regenerate or verify the GSoC dataset (`--refresh` moves the CNCF pin, `--year` limits the rebuild) |
| `npm run sync:proposals` / `check:proposals` | Regenerate or verify the proposals index |
| `npm run audit:programs` | Check the program registry (routes, data files, fact sources and dates) |
| `npm run test:e2e` | Playwright smoke test against a production build (`npm run build` first) |
| `npm run check:copy` | Fail on hype or filler words in UI copy (see `DESIGN.md` §8) |
| `npm run typecheck` | TypeScript check without emitting |
